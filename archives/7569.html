折腾博客：Z-Blog静态化改造，从Windows换到Linux

2026-11-10 23:22:43 | 作者: 月光 | 分类: 网站建设 | 评论: 0

最近我把自己的博客完成了服务器迁移，在上周正式从 Windows 服务器搬迁到了 Linux 服务器。这台服务器配置为 2 核 CPU、40G 硬盘以及 2G 运行内存，Debian 12 操作系统，环境上只装了宝塔面板 12 版本，搭配 Nginx1.30.6，专门用来存放网站的 HTML 静态文件。

按照我的估算，这套配置应对每日 30 万 PV 的访问是完全绰绰有余的，再加上我的站点本身就是纯静态网站，本身抗压能力就更强，短时间之内基本不用担忧流量带来的性能压力。

最开始我的计划，是把整个博客程序从 Z-Blog 迁移到 Hugo，前期绝大部分迁移工作其实都已经做完了。Hugo 生成出来的站点页面效果看着很不错，但有一个很大的短板：它没有可视化的网站后台，不像原来的 Z-Blog，自带集成后台，写文章、管理旧博文、发布内容都能在后台直接操作。习惯了后台操作之后，改用 Hugo 这种模式，没有便捷的管理入口，用起来处处别扭，实在适应不来。

我对于Hugo的编辑和管理界面感觉不太习惯，打算还是用原来的ZBlog进行文章管理，本地Windows11搭建了一个IIS，让AI装上SSL证书，用SwitchHosts切换域名到本地，在本地域名下新建和管理文章，然后让AI编写了一个WinSCP的同步命令，同步本地html到服务器上。

权衡过后，我放弃直接完整迁移到 Hugo，换成一套更加平滑过渡的折中方案，依旧沿用 Z-Blog 原有的内容生成逻辑，整套工作流程是这样的：

在我自己日常使用的 Windows11 本机电脑上，开启系统自带的 IIS 组件，本地搭建一套完整的博客站点，让AI装上SSL证书，再借助 SwitchHosts 工具，把我的博客域名做本地映射，访问域名就会指向本机搭建的网站，在本地域名下新建和管理文章，之后所有写稿、编辑旧文章、发布新内容，全都在本地这套环境里完成。文章编辑发布完毕，Z-Blog 就会在本地生成整套完整的静态页面，之后我再通过 WinSCP 工具，把生成好的静态文件同步上传到远端的 Linux 服务器。这还需要让AI编写了一个 WinSCP 的同步命令，排除本地的asp、mdb等文件，不要将那些文件同步到服务器上。

整套流程实操下来不算复杂，不过中间有一些关键细节需要处理，也是这次折腾耗费心思的地方。

Z-Blog 通过 YTBuild 生成静态页面的时候，输出的 HTML 里面还会残留不少 ASP 相关的代码片段。这些残余代码放到纯静态 Nginx 环境下完全没有用处，还会让页面源码变得杂乱，并且引发大量404日志错误。我去 Z-Blog 官方插件站翻找一圈，并没有现成插件可以清理这类残留，没有现成工具，我就把这个定制化需求交给 AI，让 AI 帮我开发对应的清理插件。

不得不感慨现在 AI 的编程能力确实很厉害，Z-Blog ASP算是一个很冷门的软件，AI接到我的需求之后，先去 GitHub 拉取了 Z-Blog 的完整源码，读懂内部逻辑之后，根据我的需求直接写代码，十几分钟就完成了插件代码编写，然后AI自己用VBS测试通过。

我把写好的插件放到本地站点启用测试，没想到直接一次就运行成功，没有出现任何错误。装上这个插件之后，生成出来的 HTML 源码干干净净，彻底清除掉全部 ASP 遗留标记，效果完全达到我的预期。如果有同样需求的朋友，也可以点击这里下载这个插件使用。

生成完成之后，就是 WinSCP 的同步策略。在配置 WinSCP 同步任务的时候，我设置了文件过滤规则，禁止把 *.asp;*.mdb;*.bat;*.config 这类服务器配置与数据库类文件上传到线上，只同步页面所需的其余文件。

我不想每次发布都把全站文件完整重传一遍，因此走命令行模式实现增量同步，已经上传过、没有改动的文件直接跳过，只同步发生修改的文件，整个同步命令让AI帮我编写出来。

第一次执行全量同步的时候，因为文件数量多，速度会偏慢。但后续更新发布就十分轻快，没有改动的文件直接跳过，只传输新增和修改过的资源，效率很高。

这套发布模式，虽说多了本地搭建环境这一步，本地写内容再同步上传，对比直接在线后台发布要稍微多了几道手续，但收益十分可观，线上服务器不需要再跑 ASP、PHP，也不用部署数据库服务，线上机器的CPU、内存资源得到极大释放，开销被压到很低，可以用来承接更大的并发连接，整个服务器的安全性也大幅提高，整体来看这笔代价非常值得。

实际使用感受下来，新服务器的响应速度十分惊艳，打开页面如同行云流水一般畅快，体验感非常好。这次服务器迁移改造整体算是相当成功，我甚至有点后悔没有早几年做这件事，要是早点完成切换，就能避开过去一大堆服务器维护上的糟心事。再加上现在可以借助 AI 辅助处理开发、调试工作，博客整体的管理、维护成本都下降了一大截。

最后遗留下来的问题是，由于博客全部切换为静态 HTML ，因此评论功能和打分功能暂时无法实现，需要稍后研究研究通过什么方法能够实现替代。
